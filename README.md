# Poseidon

**A maritime investigation workspace for reviewing vessel activity near Marine Protected Areas (MPAs).**

Poseidon brings Global Fishing Watch event data, public-source research, vessel details, and an agent investigation trail into one place. It helps reviewers decide which cases deserve a closer look and presents the evidence and its limitations in a cited brief. The primary deployment is a Databricks App: a Databricks job runs the investigation notebook, publishes results to a Unity Catalog Volume, and the Node app serves them. With an on-demand job attached, the app can also launch an investigation for a selected case.

Every case is a **lead flagged for review, not proof of illegal activity**. AIS gaps do not show where a vessel travelled while its signal was absent. The globe displays recorded observations from the loaded dataset; it is not a live vessel-position feed.

## Databricks App deployment

The main version of Poseidon is the Node app deployed as a Databricks App. It reads the published snapshot from a Unity Catalog Volume and can start a Databricks job to investigate a selected case.

1. Deploy the repository as a Databricks App using [`app.yaml`](app.yaml). It starts the app with `node server.mjs`.
2. In the app's **Resources**, attach the Unity Catalog export volume under the resource key `poseidon-exports`, with read access. The supplied `app.yaml` already maps this resource to `POSEIDON_VOLUME`.
3. Make sure the app identity can read the snapshot at `<volume>/poseidon_snapshot.json`. The backend notebook must publish that file to the same volume.

That connects the app to the published Databricks snapshot. To enable **Investigate now** for a selected case, create the on-demand notebook job from [`deploy/poseidon-investigate-case.job.json`](deploy/poseidon-investigate-case.job.json), attach it as the `poseidon-investigate` app resource with **Can manage run**, and uncomment the `POSEIDON_JOB_ID` binding in `app.yaml`. Give the job identity access to the notebook, required secrets, model endpoint, and export volume.

The separate scheduled pipeline uses [`notebooks/poseidon.py`](notebooks/poseidon.py); [`deploy/poseidon-hourly.job.json`](deploy/poseidon-hourly.job.json) is its hourly job template. See [`app/README.md`](app/README.md) for the detailed investigation-job setup.

### Preview the Node app locally

You need **Node.js 22 or newer**. From the repository root, run:

```bash
npm start
```

Open [http://127.0.0.1:3000](http://127.0.0.1:3000). Press **Ctrl+C** in the terminal to stop the server. It reads `data/poseidon_snapshot.json` by default; the browser needs no credentials to browse that publication.

## Run the local Python demo in VS Code

The repository also includes a Python-hosted version for local demos. It can browse the included snapshot without API keys.

### One-time setup

Open the repository folder in VS Code. In the VS Code terminal, install the Python app's dependencies:

```bash
python -m pip install -r python-app/requirements.txt
```

### Each time you want to open it

1. In VS Code's Explorer, open `python-app/app.py`.
2. Click **Run Python File** in the top-right corner of the editor.
3. In the terminal, find the address printed after `Poseidon Python App listening on` and open it in your browser. By default, it is [http://127.0.0.1:8000](http://127.0.0.1:8000).

Leave the Python process running while you use the app. To close it, focus the terminal and press **Ctrl+C**. To use another port, set the `PORT` environment variable before running `app.py`.

## What you can explore

- Browse published vessel cases and protected areas on an interactive globe.
- Review event timelines, vessel identity, risk-score reasons, cited sources, and investigation notes.
- Explore news and area context included with the publication.
- Open the historical replay from **About**.
- Review the snapshot's publication time, observation window, and data notes.

The app reads a published JSON snapshot, so opening it locally does not fetch fresh vessel observations. Local investigations can use evidence already in the snapshot; fresh data and research require the relevant credentials and services.

## How it works

The Databricks notebook collects and investigates cases, then publishes a JSON snapshot for the website. The web app reads that snapshot and displays its evidence. During an investigation, the agent can choose from permitted checks; Python executes the selected tool, records the result, and calculates the score. The final brief includes sources, caveats, and missing information.

```text
Global Fishing Watch + public sources
                 ↓
       Databricks notebook
                 ↓
 Cases, investigation trace, cited brief
                 ↓
         JSON publication
                 ↓
        Poseidon web app
```

Risk scores are calculated by code, not generated by the model. Case status describes investigation progress, not whether a vessel complied with the law. When a model is unavailable, the backend can use a rule-based policy.

## Databricks integration notes

The Node app reads the published snapshot from the attached Unity Catalog Volume through the Databricks Files API. If the investigation job is attached, the app can submit a case investigation, check its progress, and show the result. Databricks app credentials stay on the server; workspace tokens are not sent to the browser. Keep GFW and search-provider secrets in Databricks secret scopes and grant the job identity only the required access.

See [`app/README.md`](app/README.md) for the detailed job setup and [`deploy/`](deploy/) for the job definitions. The JavaScript and Python test suites use local fixtures and mocks; they do not prove the app has working permissions in a live Databricks workspace.

## Development

Run the JavaScript test suite from the repository root:

```bash
npm test
```

The Python backend tests can be run with:

```bash
python -m unittest discover -s tests -v
```

The tests use local fixtures and mocks. They do not verify access to a live Databricks workspace or external data providers.

## Data attribution and limits

Poseidon uses data from [Global Fishing Watch](https://globalfishingwatch.org/). Follow the applicable API and dataset terms, including attribution and non-commercial-use restrictions. Preserve source links and the “lead flagged for review” disclaimer when reusing the interface or its reports.

AIS coverage, vessel identity records, and event classifications can be incomplete. Public reporting can refer to later events or similarly named vessels. Review the linked evidence and the case's caveats before drawing conclusions.
